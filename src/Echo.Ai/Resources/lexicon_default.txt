# Sert de "context_bias" pour Voxtral : oriente la transcription vers ces termes
# metier pour eviter qu'ils soient rendus en mots courants qui se ressemblent
# (ex. "S2C" -> "essai to see", "COPIL" -> "copilote"). 1 terme par ligne ;
# les lignes commencant par # sont ignorees ; les espaces internes sont
# remplaces par "_" automatiquement (contrainte API mono-token).
#
# CONSERVATEUR PAR DESIGN : sur-biaiser DEGRADE le taux d'erreur (surtout en FR,
# ou ce biaisage est "experimental"). On ne garde donc QUE des sigles, noms
# propres d'outils, et termes composes distinctifs reellement mal transcrits ;
# PAS de mots courants. Pour desactiver entierement : variable VOXRA_CONTEXT_BIAS=0.
#
# Ce fichier est GENERIQUE (aucune donnee client) et VERSIONNE. Le jargon
# specifique a une mission/un client va dans un fichier LOCAL "context_bias.txt"
# (a cote, ignore par git, fusionne automatiquement avec celui-ci).
#
# FORMAT ETENDU (retrocompatible, cf. Lexicon.cs) :
#   - un terme simple, un par ligne          -> "SteerCo"
#   - un mapping variantes deformees=>forme canonique, pour la CORRECTION
#     post-transcription (les variantes sont remplacees par le canonique) :
#         "stirco|steer co=>SteerCo"
#     Le canonique seul alimente le biaisage Voxtral ; les variantes ne servent
#     qu'a la correction (passe deterministe). Les deux formes peuvent cohabiter.
